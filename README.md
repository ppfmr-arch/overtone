# Overtone

Десктопный плеер: один поиск сразу по нескольким источникам, чёрно-серый интерфейс.
Ядро на Rust, оболочка на Electron.

## Скачать

Установщик для Windows — в [последнем релизе](https://github.com/ppfmr-arch/overtone/releases/latest).
Подписи у него нет, поэтому при первом запуске SmartScreen поругается —
**Подробнее → Выполнить в любом случае**.

## Как устроено

```
core/          Rust: HTTP-сервер на 127.0.0.1 (случайный порт)
  providers/   ytmusic · soundcloud · local — по одному файлу на источник
  stream.rs    прокси аудио с поддержкой Range (перемотка)
app/           Electron: только интерфейс, вся логика источников — в ядре
```

Electron запускает `mp-core.exe` дочерним процессом и читает из его stdout строку
`MPCORE_READY <порт> <ключ>`. Порт выдаёт ОС, поэтому несколько копий не конфликтуют.

Ключ живёт ровно одну сессию и никуда не записывается. Каждый запрос к API обязан
нести его параметром `t`, иначе ядро отвечает 401. Без этого до фонотеки дотянулась
бы любая открытая в браузере страница: порт локальный, но перебирается за секунды,
а CORS здесь заведомо разрешающий — иначе рендерер с `file://` сам не сможет ходить
в API.

Аудио не грузится в браузер напрямую: `<audio>` смотрит на
`http://127.0.0.1:<порт>/api/stream/<провайдер>/<id>`, а ядро уже ходит наружу
со своими заголовками. Иначе не работали бы ни CORS, ни перемотка, ни
короткоживущие ссылки googlevideo.

## Источники

| Источник | Поиск | Воспроизведение |
| --- | --- | --- |
| SoundCloud | да | да |
| Локальные файлы | да | да |
| YouTube Music | да | да, через скрытое окно сайта |

### Про YouTube

Поиск идёт через Innertube по двум вкладкам сразу — `Songs` и `Videos`. Одной
вкладки мало: `Songs` — это лицензированный каталог, а всё, что живёт на YouTube
пользовательскими загрузками (старый андеграунд, каверы, редкости), лежит только
в `Videos`. Общий фильтр без типа не годится — он тянет ещё плейлисты и подкасты.
Склеенные списки ранжируются по числу совпавших слов запроса: каждая вкладка
отсортирована лишь внутри себя, и без общего ранжирования два десятка чужих
однофамильцев встают раньше единственного точного попадания.

С воспроизведением сложнее, и дорогу к рабочему решению стоит записать — все три
варианта ниже проверены на практике, а не взяты из документации.

**Прямая ссылка на аудио — нет.** Все клиенты Innertube (`IOS_MUSIC`, `ANDROID_VR`,
`TVHTML5`, `WEB`, `MWEB`) отвечают `Sign in to confirm you're not a bot`. То же
самое говорит `yt-dlp`, даже с JS-рантаймом: в отладочном выводе видно
`PO Token Providers: none`. Обойти это без cookies можно только генератором
PO-токенов — отдельный плагин плюс локальный сервер, который ломается при каждом
изменении на стороне YouTube.

**Встраиваемый IFrame-плеер — тоже нет.** Он отвечает ошибкой 150 на любой ролик,
включая заведомо встраиваемые. Дело не в треках и не в IP: тот же ролик
прекрасно встраивается с настоящего сайта по https. YouTube просто не принимает
`http://127.0.0.1` как origin.

**Что работает — сам сайт.** Приложение держит скрытое окно с настоящим
`music.youtube.com` и управляет обычным `<video>` на странице. Origin настоящий,
ограничения на встраивание не действуют, PO-токенами занимается собственный плеер
сайта. Ни cookies браузера, ни вход в аккаунт, ни сторонние утилиты не нужны.

Окно живёт в отдельной сессии (`persist:ytmusic`) и с браузером пользователя никак
не пересекается. При первом запуске YouTube показывает страницу согласия с
условиями — окно откроется само, согласиться нужно вручную, один раз. Дальше оно
работает скрытно; открыть его снова можно в **Настройки → Показать окно YouTube**.

Плата за такой способ ровно та же, что при прослушивании на сайте: анонимному
слушателю могут проигрываться реклама и подводки.

### Про SoundCloud

`client_id` вытаскивается из бандла веб-плеера и кэшируется; при 401 сбрасывается
и берётся заново. Отдельно нужен `track_authorization` из карточки трека — без
него media-эндпоинт отвечает 404 на что угодно. Треки, доступные только по
подписке или закрытые в регионе, не заиграют.

## Добавить свой источник

Реализовать трейт `Provider` (`core/src/providers/mod.rs`) — `search` и `resolve` —
и дописать строку в `Registry::new`. Интерфейс, фильтры и плейлисты подхватят
новый источник сами, без правок фронтенда.

## Данные

Плейлисты, любимое и список папок лежат в
`%APPDATA%\Overtone\library.json`. Запись атомарная, через временный файл.

Скрытая сессия YouTube — куки, согласие, кэш — лежит отдельно, в
`%APPDATA%\Overtone\Partitions\ytmusic`. Удаление этой папки сбрасывает YouTube:
условия придётся принять заново, один раз.

## Discord

В профиле показывается «Слушает Overtone» с названием, исполнителем и полосой
прогресса. Обложка подтягивается для YouTube Music и SoundCloud; локальные файлы
отдаются с `127.0.0.1`, и Discord, который забирает картинку со своей стороны,
до них не дотянется.

Присутствие привязано к приложению в [портале разработчика](https://discord.com/developers/applications):
оттуда берутся имя над статусом и ключи картинок. Чужой идентификатор задаётся
переменной `OVERTONE_DISCORD_APP_ID` без пересборки; пустое значение выключает
фичу целиком. Необязательно: ассеты с ключами `cover`, `play` и `pause` заменят
пустое место иконками — без них статус останется текстовым.

Готовой библиотеки здесь нет: `discord-rpc` в npm заброшен, а весь протокол —
кадры `[опкод u32 LE][длина u32 LE][JSON]` в именованный пайп `discord-ipc-N`.

## Сборка установщика

```bash
cd app && npm run dist
```

`electron-builder` кладёт `core/target/release/mp-core.exe` в ресурсы приложения —
собирать ядро в release нужно до этого.

## Оговорка

Источники опрашиваются через их внутренние веб-API, а не публичные партнёрские.
Это не запрещено технически, но условиям использования YouTube и SoundCloud
соответствует не всегда, и API могут поменяться без предупреждения.
Для личного использования — нормально; для распространения стоит перейти на
официальные API либо оставить только локальные файлы.
